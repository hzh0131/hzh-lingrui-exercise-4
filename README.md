`lrg` 是一个使用 C 语言实现的简化版 `grep`。它从标准输入或指定文件中逐行读取文本，查找包含指定字面字符串的行，并根据命令行选项决定是否显示行号、是否忽略大小写，或只统计匹配行数。

> 本文面向程序使用者和验收者。构建命令以项目源文件位于 `src/lrg.c` 为例；如果你的源文件实际位于项目根目录，请将命令中的 `src/lrg.c` 改为 `lrg.c`。

## 功能范围

支持以下选项，选项必须出现在 `PATTERN` 之前：

| 选项 | 作用 |
|---|---|
| `-n` | 在每条匹配结果前显示行号 |
| `-i` | 忽略英文字母大小写 |
| `-c` | 不显示匹配行，只输出匹配行数 |
| `-nic` | 可将支持的选项组合在一起；例如 `-nic` 等价于 `-n -i -c` |
| `--` | 结束选项解析；后续第一个参数作为 `PATTERN` |

`PATTERN` 按**普通字面字符串**匹配，不会被解释为正则表达式。例如，模式 `err.*` 只匹配文本中连续出现的 `err.*` 字符，而不是匹配 `err` 后任意字符。

输入来源有两种：

- 指定一个或多个文件：`lrg ... FILE...`
- 不指定文件：从标准输入读取，因此支持键盘输入、管道和输入重定向。

## 构建方法

### 环境要求

- Linux 或其他提供 `open()`、`read()`、`close()` 等 POSIX 接口的环境
- GCC
- 项目源文件 `src/lrg.c`（如实际文件位置不同，请相应调整路径）

### 编译

在项目根目录执行：

```sh
gcc -std=gnu11 -Wall -Wextra -g src/lrg.c -o lrg
```

编译成功后，当前目录会生成可执行文件 `lrg`。运行：

```sh
./lrg --help
```

当前实现没有专门的 `--help` 选项，因此该命令会按非法选项处理并打印用法提示。查看用法时，可直接参考本 README 中的命令格式：

```text
./lrg [-nic] PATTERN [FILE...]
```

如果源文件位于项目根目录，编译命令改为：

```sh
gcc -std=gnu11 -Wall -Wextra -g lrg.c -o lrg
```

## 使用说明

基本格式：

```text
./lrg [-nic] PATTERN [FILE...]
```

- `PATTERN` 是必需参数，表示要查找的字面字符串。
- `FILE...` 是可选的一个或多个输入文件。
- 不提供文件参数时，程序从标准输入读取，输入结束后才会完成统计并退出。
- 选项放在 `PATTERN` 前面；本程序不支持在 `PATTERN` 后继续添加选项。
- 多个文件作为输入时，匹配结果会带上文件名前缀，便于区分来源。
- `-c` 只输出匹配行数；多个文件时，每个文件分别输出计数。

### 标准输入结束方式

- 交互输入：输入完成后按 `Ctrl+D`（在 Linux 终端中表示输入结束）。
- 管道：上游命令结束后，程序会读到输入结束。
- 重定向：文件读完后，程序会读到输入结束。

## 运行示例

以下示例先创建可重复使用的测试文件。命令和输出中的文件内容均在示例中明确给出。

```sh
cat > sample.log <<'EOF'
INFO server started
ERROR disk full
error connection lost
INFO request complete
EOF
```

### 示例 1：查找字面字符串

命令：

```sh
./lrg error sample.log
```

输出：

```text
error connection lost
```

说明：默认区分大小写，因此 `ERROR disk full` 不会匹配小写模式 `error`。

### 示例 2：忽略大小写并显示行号

命令：

```sh
./lrg -in error sample.log
```

输出：

```text
2:ERROR disk full
3:error connection lost
```

说明：`-i` 忽略大小写，`-n` 显示匹配行在输入中的行号。

### 示例 3：只统计匹配行数

命令：

```sh
./lrg -ic error sample.log
```

输出：

```text
2
```

说明：`-c` 不打印匹配行，只输出匹配行数量；`-i` 使大小写不同的 `ERROR` 和 `error` 都能匹配。

### 示例 4：通过管道读取标准输入

命令：

```sh
printf 'alpha\nERROR found\nbeta\n' | ./lrg -i error
```

输出：

```text
ERROR found
```

说明：未指定文件时，程序从文件描述符 `0`（标准输入）读取数据。管道和 `<` 重定向都使用同一条标准输入处理路径。

### 示例 5：同时搜索多个文件

创建第二个文件：

```sh
cat > other.log <<'EOF'
warning only
error in worker
EOF
```

命令：

```sh
./lrg -n error sample.log other.log
```

输出：

```text
sample.log:3:error connection lost
other.log:2:error in worker
```

说明：指定多个文件时，输出会带文件名前缀。该示例仍区分大小写，所以 `sample.log` 中大写的 `ERROR` 不匹配。

## 设计说明

### 模块划分

| 模块 | 主要职责 |
|---|---|
| `parse_arguments()` | 从左向右解析选项、`PATTERN` 和第一个文件参数；遇到不支持的选项或缺少 `PATTERN` 时报告用法错误 |
| `read_file()` | 打开指定文件；打开成功后调用 `scan_fd()`，处理完后关闭文件 |
| `scan_fd()` | 从给定文件描述符读取数据，处理 `read()` 中断，管理当前行缓冲区，处理最后一行并统计匹配结果 |
| `process_lines()` | 扫描每次 `read()` 得到的数据块；将字符累积成完整行，遇到换行符时进行匹配和输出 |
| `strstr_ignore_case()` | 在忽略大小写的条件下进行字面字符串匹配 |
| `main()` | 区分标准输入和文件输入，汇总是否匹配、是否发生文件错误，并决定最终退出码 |

### 数据读取与行处理流程

1. `main()` 解析命令行参数，确定模式、选项和输入源。
2. 如果用户指定文件，`read_file()` 使用 `open()` 打开文件；如果没有指定文件，则直接从标准输入文件描述符 `0` 读取。
3. `scan_fd()` 通过固定大小的临时缓冲区调用 `read()`。每次读取只得到一段字节，并不保证刚好在行尾结束。
4. `process_lines()` 逐字节扫描数据块：普通字符追加到当前行；遇到 `\n` 时，给当前行补上字符串结束符 `\0`，再执行匹配、计数和输出。
5. `read()` 返回 `0` 表示输入结束。若最后一行没有以 `\n` 结束，`scan_fd()` 会单独处理缓冲区中剩余的字符。
6. 文件处理结束后，主流程汇总匹配状态与文件错误状态，返回对应退出码。

### 如何实现“行长不限”

程序每次只用固定大小的临时缓冲区（题解中的示例为 `char buf[1024]`）读取一块数据。**读取块的大小不等于一行的最大长度**：一行可以跨越多次 `read()` 调用。

当前行使用动态分配的缓冲区保存：

- `current`：当前行缓冲区的地址。
- `current_len`：当前行已保存的字符数。
- `size_of_current`：缓冲区当前容量。

追加字符前，程序检查容量是否足够。如果空间不足，就使用 `realloc()` 扩大缓冲区，题解采用容量翻倍的策略。因为行结束只由 `\n` 决定，所以不会因为一行超过 1024 或初始 4096 字节就直接截断。

“行长不限”表示没有人为设置一个较小的固定行长上限；实际仍受可用内存、`size_t` 可表示范围和内存分配成功与否限制。

### 如何实现“内存不随文件增长”

程序不会把整个文件一次性读入内存，而是重复使用固定大小的读取缓冲区，并只保留**当前尚未处理完的一行**：

- 当前行处理完成后，将 `current_len` 重置为 `0`，下一行从缓冲区开头重新写入。
- 重置长度不会清空内存，但后续字符会覆盖旧内容；输出字符串在当前行末尾写入 `\0`，不会把较短新行之后的旧字符输出出来。
- 缓冲区只在单行长度超过当前容量时扩容，而不是因为文件总行数增加就扩容。

因此，常规情况下内存占用主要取决于固定读取缓冲区和最长一行的长度，而不是整个文件的总大小。若输入包含一条非常长的行，缓冲区会相应变大；这属于按当前行长度增长，而不是按整个文件累计增长。

## 错误处理表

>下表依据题解中描述的处理逻辑整理。错误发生时，程序可能继续处理后续文件，也可能立即终止；“退出码”列区分这两种情况。

| 错误情况 | 检测位置 / 条件 | 对应行为 | 退出码或影响 |
|---|---|---|---|
| 命令行参数非法 | `parse_arguments()` 返回失败，例如出现不支持的选项 | 向标准错误输出用法提示，停止处理 | `2` |
| 缺少 `PATTERN` | 选项解析结束后没有剩余参数可作为模式 | 输出用法提示，停止处理 | `2` |
| `open()` 打开文件失败 | `open()` 返回 `-1` | 输出文件名和 `strerror(errno)` 对应的原因；主流程记录文件错误，并可继续尝试后续文件 | 最终为 `2` |
| 初始 `malloc()` 失败 | `scan_fd()` 申请当前行缓冲区时返回 `NULL` | 输出内存不足提示，并返回错误标记给调用者 | 预期由主流程记录错误并返回 `2`；需确认最终 `main()` 已传播该错误状态 |
| `realloc()` 扩容失败 | 当前行缓冲区扩容时返回 `NULL` | 输出 `lrg: out of memory`，调用 `exit(EXIT_FAILURE)` 终止程序 | `EXIT_FAILURE`（常见系统为 `1`） |
| 行长度溢出保护触发 | 行缓冲区长度达到实现中的溢出保护条件 | 输出 `lrg: line too long`，调用 `exit(EXIT_FAILURE)` 终止程序 | `EXIT_FAILURE`（常见系统为 `1`） |
| `read()` 被信号中断 | `read()` 返回 `-1` 且 `errno == EINTR` | 不把它当作普通读取失败，继续重试 `read()` | 不直接导致失败退出 |
| `read()` 发生其他错误 | `read()` 返回 `-1` 且 `errno != EINTR` | 输出文件名和错误原因，释放当前行缓冲区，并向调用者返回错误标记 | 预期最终为 `2`；需确认 `main()` 汇总了读取错误 |
| 忽略大小写匹配函数内存分配失败 | `strstr_ignore_case()` 中临时 `malloc()` 返回 `NULL` | 题解中的实现返回 `NULL`，调用方可能把它当作“未匹配” | 可能造成漏报；当前设计没有把它可靠地区分为内存错误 |
| 标准输入读取错误 | 从文件描述符 `0` 调用 `read()` 失败且不是 `EINTR` | 应输出错误并记录读取失败 | 依赖 `scan_fd()` 与 `main()` 的错误状态传递；提交前应实测确认 |

## 退出码

题解计划采用以下语义：

| 退出码 | 含义 |
|---|---|
| `0` | 至少找到一行匹配内容，且没有发生输入文件/读取错误 |
| `1` | 输入处理成功，但没有任何匹配行 |
| `2` | 参数错误，或至少一个输入源发生打开/读取错误 |
| `EXIT_FAILURE` | 发生需要立即终止的错误，例如当前实现中的 `realloc()` 失败或行长度保护触发；常见系统的值为 `1` |

如果一次命令处理多个文件，只要有一个文件失败，预期最终退出码为 `2`，即使其他文件已经找到匹配项。

## 已知限制

1. **不是完整的 GNU `grep`。** 仅支持 `-n`、`-i`、`-c` 及题解中描述的选项组合，不支持 `-v`、`-E`、`-F`、`-w` 等其他选项。
2. **只做字面字符串匹配。** `.`、`*`、`[]`、`^`、`$` 等字符不会被解释为正则表达式语法。
3. **选项位置有限制。** 选项应出现在 `PATTERN` 前面；不支持完整 GNU `grep` 的参数解析规则。
4. **大小写忽略的范围有限。** 题解使用 `tolower()` 做逐字符转换，主要面向常见英文字符；不应将其视为完整的 Unicode 大小写折叠。
5. **极长行仍受系统资源限制。** 动态扩容避免固定行长截断，但无法保证在内存耗尽时继续处理。
6. **内存错误传播仍需检查。** 题解记录的 `strstr_ignore_case()` 临时分配失败会被当成未匹配；`scan_fd()` 的错误返回也必须由最终 `main()` 正确汇总，才能保证退出码一致。
7. **输出与诊断可能因最终代码略有差异。** 本 README 的示例应在提交版本上实际运行验证；尤其要核对多文件前缀、`-c` 输出、标准输入错误和退出码。
